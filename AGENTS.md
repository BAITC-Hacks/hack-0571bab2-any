# Инструкции для обоих Codex в репозитории HackAlem AI

Прочитай `docs/TEAM_CODEX_PROMPT.md`, `docs/03_КОНТРАКТ_API.md`, `docs/BUYING_TERMS_SOURCES.md` и свою роль из последнего сообщения пользователя. Для backend прочитай `docs/CATALOG_API_SHAPE.md`, для frontend — `docs/DESIGN_BRIEF.md`. Работай только в своей ветке: `backend` для backend, `frontend` для frontend. Общие решения сначала согласуй через контракт; не переписывай чужие файлы без необходимости.

## Цель

Работающий прототип ИИ-чата ekt.kz за 5 часов: достоверный ответ по каталогу и сертификату; проверенный аналог; подтверждённые условия покупки; корзина меняется только после отдельного явного согласия и повторной проверки остатка; ссылка ведёт на актуальную корзину. Мобильный и десктопный интерфейс. Файлы PDF/DOCX/XLSX/JPEG — после устойчивого обязательного сценария.

## Работа до готовности

- Начни с осмотра репозитория и короткого плана на ближайшие 45–60 минут. Затем реализуй, проверь, исправь и повтори. Не объявляй задачу законченной, пока обязательные сценарии и общий запуск не проверены.
- Каждое улучшение подтверждай конкретным тестом, сборкой или ручным сценарием. Перед коммитом просмотри diff и проверь отсутствие секретов. Не делай ложных заявлений в README.
- В каждом часу к `xx:45` закончи текущий проверяемый этап, к `xx:50` сделай содержательный коммит и push в **свою** ветку. При ошибке push немедленно сообщи человеку; не теряй локальные изменения. Коммит, сделанный другим участником на `main`, не заменяет твой личный вклад.
- Периодически подтягивай общий контракт, но не делай force push и не сбрасывай чужую работу. Перед объединением обе ветки должны собираться и проходить интеграционный сценарий.
- Используй доступные плагины по задаче: OpenAI Developers для безопасной настройки API и официальной документации, Codex Security для проверки кода перед сдачей. Если плагина нет в аккаунте, предложи/подключи только нужный; подключение аккаунта выполняет владелец. Дополнительные плагины ставь лишь при конкретной пользе и без раскрытия данных партнёра.

## Данные и безопасность

- Не вставляй реальные API-ключи или Basic Auth в чат, код, коммит, README, тестовые fixture, скриншот, логи или промпты. Не открывай `.env` для вывода содержимого. Ключи вводит владелец локально в `apps/api/.env` или менеджер секретов. Frontend ключи не получает.
- Промокоды OpenAI/NVIDIA относятся к вызовам API приложения. Они не повышают качество рассуждений Codex при разработке. Используй их только для разрешённых тестов продукта с контролем расхода.
- Данные партнёра/клиентов и исходный код третьих лиц не отправляй внешним AI-сервисам без разрешения организаторов. Для демонстрации применяй синтетический каталог. Не сканируй инфраструктуру мероприятия.
- Если нет API корзины ekt.kz, явно помечай корзину как прототип. Не сообщай выдуманные цену, наличие, сертификат, условия оплаты/доставки или срок.
- Первое «добавь товар» создаёт предложение. Только отдельное подтверждение клиента меняет корзину, после повторной проверки количества и остатка. Модель не пишет в корзину напрямую.

## Границы роли

- `backend`: владеет `apps/api`, интеграциями, серверной корзиной, тестами API; может менять общий контракт после согласования.
- `frontend`: владеет `apps/web`, адаптивным интерфейсом, клиентом API, подтверждением и страницей корзины; может работать с mock по согласованному контракту.
- Общий `README.md`, `docs/03_КОНТРАКТ_API.md`, настройки workspace и интеграционные тесты согласовывайте перед изменением, чтобы не создавать конфликт.

## Сдача

Проверь пять обязательных сценариев вместе со вторым участником. README должен содержать фактическую архитектуру, запуск, данные, ограничения и демонстрационный сценарий. Отправь финальную версию в выданный приватный GitHub-репозиторий; страницу треков и кнопку «Сдать решение» проверяет человек. Официальные критерии и дедлайн, объявленные на площадке, имеют приоритет над этим файлом.
