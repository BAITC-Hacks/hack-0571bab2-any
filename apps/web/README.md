# Встраиваемый помощник EKT

Frontend на React, TypeScript и Vite. Требования: [исходное ТЗ заказчика](../../CUSTOMER_SPEC.md), [дополнения пользователя](../../PROJECT_REQUIREMENTS.md), [контракт API](../../docs/03_КОНТРАКТ_API.md).

## Что входит

- Готовый мокап сайта (`src/EktSite.tsx`, локальные изображения и стили) служит окружением демонстрации. Его статические карточки не являются актуальными фактами API.
- Помощник изолирован в Shadow DOM. Кнопка справа внизу открывает quick chat; в заголовке доступны боковая панель и полный экран. На мобильном — нижняя панель и развёрнутый режим. Переключение размера и закрытие сохраняют текущий диалог.
- Интерфейс и запросы к серверу поддерживают русский (`ru`) и казахский (`kk`). Названия и значения характеристик отображаются так, как их передал каталог.
- Карточки показывают источник, наличие, характеристики, цену и сертификат при наличии данных. Аналоги сопровождаются серверным обоснованием и доступными отличиями характеристик.
- Добавление разделено на запрос предложения и отдельное подтверждение. Изменённое количество требует нового предложения. Повтор подтверждения использует тот же ключ идемпотентности; неизвестный результат запроса не считается успешным добавлением.
- PDF, DOCX, XLSX и JPEG размером до 2 МиБ передаются на `/api/attachments`. Найденные артикулы и количества требуют ручной проверки. Проверка позиции готовит предложение, но не меняет корзину. Для внешнего анализа фото предусмотрено отдельное согласие; дополнительно необходимо разрешение обработки на сервере.

## Локальный запуск

Из корня репозитория:

```bash
cd apps/web
npm ci
npm run dev
```

Открыть `http://localhost:5173/`. Нужен отдельно запущенный backend по его [инструкции](../api/README.md). Vite проксирует `/api/*` на `http://127.0.0.1:3001`. Другой адрес задаётся только для dev-сервера:

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:3002 npm run dev
```

У backend `WEB_ORIGIN` должен совпадать с адресом страницы браузера, например `http://localhost:5173`. Для безопасной демонстрации использовать серверный синтетический каталог (`CATALOG_MODE=demo`) без внешних AI-вызовов. Frontend больше не использует отдельный mock-режим `?demo=1`: он получает факты и корзину от API.

При интеграционной проверке `origin/backend` от 23.09.2026 обнаружено: его `npm ci` останавливается с `Missing: api@0.1.0 from lock file`. Это блокер чистого совместного запуска, который должен исправить владелец backend. Для временного локального запуска выполнен `npm install` **только в отдельном архиве backend в `/tmp`**, без изменения серверной ветки. Успешная frontend-сборка сама по себе не означает готовность общего проекта.

## Сборка и подключение к сайту

```bash
npm run build
```

Результаты: `dist/` — демонстрационный сайт, `dist-widget/ekt-assistant.js` — один JS-файл виджета с React и его стилями. Файлы мокапа магазина не нужны для подключения самого помощника.

На странице сайта после загрузки `body`:

```html
<script src="/assets/ekt-assistant.js"></script>
<script>
  const removeAssistant = EktAssistant.mount({ apiBase: '/api', locale: 'ru' });
  // При необходимости демонтировать виджет: removeAssistant();
</script>
```

Повторный `mount()` не создаёт второй виджет. Параметр `apiBase` принимает путь на том же origin. В production нужен серверный proxy `/api/*` к backend и HTTPS; Vite proxy работает только при разработке. Cookie сессии и CSRF-токен из `GET /api/cart` используются клиентом автоматически. API-ключи и Basic Auth не передаются браузеру и не входят в сборку. На сайте с CSP разрешить файл виджета и его стили согласно политике владельца сайта.

Для кнопки в интерфейсе сайта можно вызвать:

```js
window.dispatchEvent(new Event('open-assistant'));
```

Событие `ekt-cart-snapshot` передаёт актуальный ответ корзины в `event.detail`; мокап использует его для счётчика. Это событие само не изменяет корзину партнёра. Реальное подключение к ekt.kz требует согласованной серверной интеграции с его сессией и API корзины.

## Данные и ограничения

- Текущий backend возвращает собственную **корзину прототипа**, ссылка ведёт на `/cart` текущего сайта. Оформление заказа и реальная корзина ekt.kz не подключены. Страница корзины читает актуальное состояние той же серверной сессии.
- Неизвестные цена, остаток и сертификат явно обозначаются как отсутствующие данные. В текущем контракте нет изображения товара: используется нейтральная иконка, а не фотография другого товара.
- Поддерживаются современные форматы Word/Excel (`.docx`, `.xlsx`); старые `.doc`/`.xls` текущий API не принимает. Фото без разрешённой внешней обработки возвращает результат для ручной проверки; модель не гарантирует распознавание.
- Переключение режима сохраняет состояние в памяти. Последние 40 сообщений хранятся в `sessionStorage` вкладки с ограничением восстановления 30 минут. Содержимое файлов, CSRF-токены и действующие предложения там не сохраняются. Обновлённая страница требует свежего предложения перед добавлением.
- Серверная сессия и корзина текущего прототипа находятся в памяти backend. После перезапуска сервера старое предложение недействительно; клиент запрашивает новую сессию и предлагает повторить подготовку.
- Условия покупки показывает backend с источником. Неизвестная минимальная партия и спорные условия доставки не превращаются в гарантированные факты.

## Проверка пяти обязательных сценариев

### Выполненные проверки 23.09.2026

- Сборка frontend и отдельного виджета прошла (`npm run build`). В завершённом прогоне прошли 9 браузерных проверок frontend с подставленными ответами API. Эти проверки подтверждают UI и клиентский протокол; они не заменяют интеграцию с сервером.
- В ручном сценарии с синтетическим backend после отдельного подтверждения добавлены 2 единицы, переход по ссылке открыл актуальную корзину с количеством 2.
- Отдельно через настоящий `/api/attachments` проверены четыре малых синтетических файла. PDF вернул `ABC-123 × 2` с низкой уверенностью, DOCX и XLSX — ту же позицию с высокой. Все ответы потребовали ручной проверки. JPEG без согласия вернул честный `manual_review / CUSTOMER_CONSENT_REQUIRED` без кандидатов и внешнего AI-вызова. Все четыре ответа — HTTP 200, `cartChanged: false`; корзина до и после оставалась пустой.
- Чистый совместный запуск остаётся ограничен описанной выше ошибкой `npm ci` backend. Подключение к настоящей корзине ekt.kz не проверялось и не заявляется.

### Приёмочный сценарий

Повторять с запущенным backend в новой сессии браузера, сначала на ПК, затем на ширине 390 px.

1. Спросить `Есть ABC-123?`: синтетический остаток 4, характеристики и пометка демо. Если API вернул сертификат — проверить ссылку; в стандартном demo-каталоге сертификат отсутствует и это должно быть видно.
2. Спросить `Есть ABC-000?`: остаток 0, аналог `ABC-124` с причиной совместимости.
3. Спросить `Какие оплата, доставка и минимальная партия?`: содержательный ответ, ссылка на публичные условия, честное указание неподтверждённой минимальной партии.
4. Спросить `Добавь 2 шт. ABC-123`: появляется предложение, до отдельного подтверждения `/cart` остаётся пустой. После «Подтвердить и добавить» — ровно 2; повторный быстрый клик не должен добавить ещё 2. Попытка добавить ещё 3 не должна превышать доступный остаток 4.
5. Перейти по выданной ссылке на корзину: та же позиция и количество 2. Проверить обновление счётчика мокапа.

Дополнительно: переключить quick → panel → full → закрыть/открыть без потери диалога; проверить RU/KK, клавиатурную навигацию, мобильную прокрутку/поле ввода и повтор после ошибки сети. Загрузить небольшие синтетические PDF/DOCX/XLSX/JPEG, проверить ручное подтверждение распознавания и отсутствие автоматического изменения корзины.
